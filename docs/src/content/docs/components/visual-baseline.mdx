## Visible surface test

Status components must be visible **without** relying on iOS glass, blur, notification-shade blending, or dark overlays.

### Rules

1. **Background** — status fill must differ from the surface behind it
2. **Border** — 1px semantic border defines the edge
3. **Text** — semantic text color stays readable (WCAG AA on the fill)
4. **No blur dependency** — if a badge only looks correct over glass, the tokens are wrong

### Surfaces tested

| Surface | Token reference |
| ------- | ---------------- |
| White | `#FFFFFF` |
| App background | `color.bg.default` |
| Card | `color.surface.raised` |
| Glass | `color.glass.surface` |
| Dark | `color.surface.default` (dark) |

Run: `cd apps/example && bun run ios` (or `android`). Full checklist: [Example app guide](/guides/example/).

### Device checklist (summary)

**Light + dark on iPhone-sized simulator and one Android emulator:**

1. Modal/Dialog never flush to screen edges (host inset visible)
2. Form-in-modal: primary action stays above keyboard (iOS)
3. Alert title + body share severity hue without manual color props
4. Toast action label readable; Snackbar uses elevated surface
5. Badge default and accent readable on app background
6. Backdrop tap and hardware back dismiss where `onClose` is set
